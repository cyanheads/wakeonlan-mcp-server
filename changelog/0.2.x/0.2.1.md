# 0.2.1 — 2026-11-21

## Changed

- **HTTP transport** — JWT mode logs a startup warning when `MCP_AUTH_SECRET_KEY` is set without `MCP_JWT_EXPECTED_AUDIENCE`, and `.env.example` lists that variable and `MCP_JWT_EXPECTED_ISSUER`. `MCP_HTTP_ENDPOINT_PATH` is normalized and `MCP_PUBLIC_URL` validated at startup, and HTTP error responses echo the request's JSON-RPC `id` (mcp-ts-core 0.13.20, 0.13.21).
- **Argument rejections** — a wrong-typed value for a bounded argument no longer also reports the `too_big` / `too_small` issue Zod raises for the bound (mcp-ts-core 0.13.22).
- **`wakeonlan-guide` skill** — gate 4 says every probe that connects is a logged pre-auth disconnect on an SSH port (skill version 1.1).
- **Bun** — `engines.bun` `>=1.4.0` → `>=1.4.4`, and the README prerequisite follows.
- **Skills and scripts** — `framework-skills/`, `scripts/`, `changelog/template.md`, and the agent protocol resynced to mcp-ts-core 0.13.22; `tests/scripts/bundle-agent-docs.test.ts` imports `lint-packaging` directly.

## Fixed

- **`wol_wake_host` confirmation ended before the wait window expired** ([#4](https://github.com/cyanheads/wakeonlan-mcp-server/issues/4)) — a last probe runs when `wait_for_s` ends, `not_reachable` follows only that probe, and a port answering then reads `awake`. The call returns within `wait_for_s` + 3 seconds (58 at the 55-second cap), and `probe.attempts` on `not_reachable` is one higher. The tool description, `wait_for_s`, `state`, and `time_to_answer_ms` descriptions, the README, and `wakeonlan-guide` gate 2 state it.
- **Aliases rendered unescaped in `content[]`** ([#7](https://github.com/cyanheads/wakeonlan-mcp-server/issues/7)) — the headings of `wol_list_hosts`, `wol_check_host`, and `wol_wake_host`, and the aliases quoted in `unknown_host`, `no_address`, `off_segment`, and `wake_in_progress` text, are code spans. An alias such as `nas._x_` reads back exactly and copies into `alias`; `structuredContent` is unchanged.
