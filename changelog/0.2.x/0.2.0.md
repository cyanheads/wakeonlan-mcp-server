# 0.2.0 — 2026-10-28

## Added

- **`wakeonlan-guide` agent skill** — served over MCP as `skill://wakeonlan-guide/SKILL.md` (listed in `resources/list` beside the `skill://{+path}` template) through `createApp({ skills })` (mcp-ts-core 0.13.18, [cyanheads/mcp-ts-core#789](https://github.com/cyanheads/mcp-ts-core/issues/789)), and shipped under `skills/` in the npm package, the `.mcpb` bundle, and the Docker image. It covers when to wake versus check, reading `refused` / `no_answer` / `not_reachable`, the wake-failure checks that need a person at the target, and adding a host.
- **Agent Plugins root manifests** — `plugin.json` and `mcp.json` (Agent Plugins 1.0.0, read by Codex, Cursor, GitHub Copilot, VS Code, and Kiro).

## Changed

- **Operator-written text reads back as written** — `wol_list_hosts` and `wol_wake_host` Markdown-escape host descriptions, guidance, interface names, and the hosts-file path in `content[]`, so a CommonMark parse returns exactly what was configured where 0.1.2 rendered emphasis, links, and headings; a trailing ` #` survives too (mcp-ts-core 0.13.18, [cyanheads/mcp-ts-core#781](https://github.com/cyanheads/mcp-ts-core/issues/781)). `structuredContent` is unchanged.
- **Tool error text is Markdown-escaped in `content[]`** — the `Error:` and `Recovery:` lines (mcp-ts-core 0.13.16, [cyanheads/mcp-ts-core#760](https://github.com/cyanheads/mcp-ts-core/issues/760)). `structuredContent` is unchanged.
- **An out-of-range or fractional framework variable stops startup with a banner naming the variable** — `MCP_HTTP_PORT=3010.5` now fails with `MCP_HTTP_PORT (mcpHttpPort): Invalid input: expected int, received number`; 0.1.2 started with the same value (mcp-ts-core 0.13.16, [cyanheads/mcp-ts-core#747](https://github.com/cyanheads/mcp-ts-core/issues/747), [cyanheads/mcp-ts-core#746](https://github.com/cyanheads/mcp-ts-core/issues/746)).
- **README** — a wake ends `not_reachable` for both `refused` and `no_answer`; `probe.last_outcome` and `guidance` tell them apart.
- **Bundle packaging** — `.mcpbignore` is root-anchored per the 0.13.18 template, and `skills/` is in the npm `files` and copied into the Docker image. The bundle cleaner and the packaging check strip agent docs only at a package root, so the MCP SDK's `dist/ext/skills/` runtime stays in the `.mcpb` (local port of the fix for [cyanheads/mcp-ts-core#794](https://github.com/cyanheads/mcp-ts-core/issues/794), with `tests/scripts/bundle-agent-docs.test.ts`).
- **`bunfig.toml`** — `minimumReleaseAge` 3 days → 1 day. Bun 1.4.2 → 1.4.4 (`packageManager`, `Dockerfile`, README badge).
- **Skills** — `framework-skills/` resynced to mcp-ts-core 0.13.18, including the new `add-skill`.
